2. Solve・Rôleplay — Guild Members

Solve・Rôleplay synchronizes a defined set of roleplay roles between two controlled Solve guilds. When a member joins the second guild, the bot receives the member-join event, finds the same Discord user in the first guild, reads only the configured source roles, and applies their configured equivalents. Authorized administrators can also run a complete reconciliation over existing members after configuration changes or downtime.

Member joins RP #2→Match same user in RP #1→ Read mapped roles→Apply equivalents in RP #2

Relevant implementation excerpt

@commands.Cog.listener()
async def on_member_join(self, member: disnake.Member):
    if member.guild.id != RP2_GUILD_ID:
        return
    await self.sync_member_roles(member)

# Administrator-only full reconciliation
members_to_sync = [member for member in rp2_guild.members if not member.bot]
for member in members_to_sync:
    await self.sync_member_roles(member)

The event-driven join flow requires GUILD_MEMBER_ADD. The reconciliation flow requires a complete, current guild member list. Interaction payloads and one-off REST lookups do not provide equivalent event coverage or a complete reconciliation source.

3. Solve・Douane — Guild Members

Solve・Douane operates the whitelist and staff workflows shared by the controlled Solve Naruto and Douane guilds. It reacts to member joins and role changes, reconciles whitelist/blacklist and staff roles, and computes the current staff or voice-queue membership used by operational tools. These features use Discord user IDs and role membership; they do not use presence data.

Member joins or roles change→Validate configured state→ Synchronize or protect roles→Write restricted audit log

Relevant implementation excerpts

@commands.Cog.listener()
async def on_member_update(self, before: disnake.Member, after: disnake.Member):
    if after.guild.id != GUILD_NARUTO_ID:
        return
    # Verify and, where necessary, correct a protected whitelist-role change.

# Staff-role reconciliation between the two controlled guilds
authorized_member_ids = {member.id for member in source_role.members}
await self._sync_douane_role(target_guild, authorized_member_ids, target_role, ...)

# Voice-queue cleanup needs the current guild membership
for member in guild.members:
    await reconcile_queue_nickname(member)

The join/update listeners require member Gateway events. Staff-role and administrative reconciliation require complete role-member and guild-member collections. Access is scoped to the two configured Solve guilds and is used only for those operational workflows.

4. Solve・Douane — Message Content

Message content is processed only in explicitly configured operational channels and for four deterministic features. It is not used for advertising, profiling, general analytics, or training machine-learning or artificial-intelligence models.

FeatureWhy ordinary message content is necessaryScope
Absence forwarding Copies a staff member’s absence notice between the configured Naruto and Douane absence channels. Two fixed operational channels; messages from bots are ignored.
Staff mention routing Detects one configured staff-role mention and forwards the accompanying context to the restricted staff destination. Configured guild/channel/role only.
Douane guidance Applies deterministic keyword and mention rules to route questions and respond to unauthorized staff pings. No AI or semantic profiling; fixed rules only.
Ticket transcripts Creates the staff audit transcript when an authorized user closes a Douane ticket. Ticket channels only; restricted log destination.

Relevant implementation excerpts

@commands.Cog.listener()
async def on_message(self, message: disnake.Message):
    if message.author.bot:
        return
    if message.guild.id == DOUANE_GUILD_ID and message.channel.id == ABSENCE_CHANNEL_DOUANE:
        forwarded_text = f"**Absence de :** <@{message.author.id}>\n{message.content}"
        await configured_naruto_absence_channel.send(forwarded_text)

# On authorized ticket closure
with temporary_transcript.open("w", encoding="utf-8") as transcript:
    async for message in ticket_channel.history(limit=None, oldest_first=True):
        transcript.write(format_ticket_line(message))
await restricted_log_channel.send(file=disnake.File(temporary_transcript))
temporary_transcript.unlink(missing_ok=True)

Slash commands cannot replace these passive workflows because the triggering objects are ordinary staff notices, role mentions, questions, and ticket messages. The bot first checks the configured guild, channel, role, author, or ticket context before using content.

5. Data handling and user controls

  • Access is restricted to the application operator and authorized Solve staff.
  • Persistent workflow records use access-controlled hosting and database services.
  • A ticket transcript is written to a temporary local file only during closure, transferred to a restricted Discord log channel, and deleted from local storage immediately afterward.
  • Message content is not sold, used for advertising, or used for AI/ML training.
  • Data access or deletion requests can be sent to nagisa_sano on Discord or through an official Solve support ticket, as described in the privacy policy.
